===============================================================================
 1. DESIGN INTENT
===============================================================================

Target: professional engineering / simulation software, similar in spirit to
NVIDIA Isaac Sim / Omniverse, but friendlier and more modern.

  * It is a hybrid of style #2 "Boxed" and style #8 "Softbox":
      from Boxed   : near-square geometry, contained/editor tabs, left accent bar
                     on selected navigation items, bar-shaped slider thumb,
                     straight-line charts on a solid grid, dense controls.
      from Softbox : 2-3 px micro radius (not sharp, not round), dark filled
                     input fields with an underline, status tags with a dot.
      own          : docked panels with header strips, near-black seams between
                     panels, editor-style tab strip, tree with indent guides,
                     graphite + steel blue, no decorative color in the chrome.

  * "Friendlier than Isaac Sim" means:
      - 13 px UI text instead of 11-12 px, higher text contrast.
      - Every interactive state is visible: hover lightens, focus draws a blue
        underline, selection is a blue-tinted row, the active nav item gets a
        3 px blue bar, the active tab gets a 2 px blue top line.
      - Slightly more padding than typical DCC tools (30 px controls, 14 px insets).

  * "Not childish / not old-school" rules:
      - ONE accent color (steel blue). Green/amber/red appear only where they mean
        something (status: ok / warning / error), never as decoration.
      - No colored logo tile, no rainbow avatars, no red notification dots, no
        bright filled call-to-action in corners  (setting: quiet_chrome=True).
      - No gradients, no shadows, no glow. Depth comes from 3-4 neutral surface
        levels and 1 px near-black seams (#0e0f10).
      - Small, consistent radii (2-4 px) instead of 0 px (Win95) or 12+ px (web).

 2. COLOR PALETTE
===============================================================================

 Neutral graphite (very slightly cool), darkest -> lightest:

   seam          #0e0f10   1 px borders between panels, under header strips
   sidebar       #161719   menu bar, status bar (outer chrome)
   input_bg      #17181a   text fields, spin boxes, console filter
   bg            #1b1c1e   window background (shows in the gaps between panels)
   tab strip     #1e1f22   background of editor-style tab bars
   surface       #222326   panel content, editor, tables, trees
   hover row     #26282c   hovered tree/list rows
   nav active    #26282b   selected navigation item background
   surface_alt   #2a2b2f   panel header strips, table headers, combo boxes
   elevated      #2c2d31   menus, popups, dialogs, toasts
   button        #303135   default (flat tool) buttons
   border        #303135   generic 1 px borders inside panels
   button hover  #393a3f
   border_strong #3e4045   control outlines, menu borders

 Text:
   text          #e6e7e9   primary text
   text_muted    #a6a8ae   labels, secondary text, inactive tab hover
   text_faint    #73757b   placeholders, captions, inactive tabs, line numbers

 Accent (steel blue) — the only decorative color:
   accent          #4a8fe7   primary buttons, focus underline, active tab line,
                             nav bar, checked boxes, chart primary series
   accent_hover    #5f9ded
   accent_pressed  #3a7bd5
   on_accent       #ffffff   text/icons on accent
   selection       #283445   selected rows (solid mix: surface + 16% accent)
   accent_soft     #2e4a8fe7 (#AARRGGBB, 18% alpha)
   accent_soft_s.  #594a8fe7 (35% alpha) text selection in editors

 Semantic (meaning only):
   success  #5fb37a  (text on dark: #77be8e, soft bg: #295fb37a)
   warning  #d9a441  (text on dark: #dfb25e, soft bg: #29d9a441)
   danger   #e0605a  (text on dark: #e57873, soft bg: #29e0605a)
   info     #4a8fe7  (same as accent)

 Chart series (calm, low-saturation):
   #4a8fe7 steel blue, #6cb7c9 teal, #8a9bb5 slate, #d9a441 amber,
   #9a8fd1 lavender, #5fb37a green

 Code editor syntax (derived from the palette):
   keywords   = accent, semibold
   numbers    = 65% warning + 35% text
   CONSTANTS  = 55% info + 45% text
   calls()    = 75% text + 25% accent
   strings    = 80% warning + 20% text
   comments   = 65% success + 35% text_faint, italic
   current line background = surface + 4.5% text

===============================================================================
 4. COMPONENT-BY-COMPONENT LOOK
===============================================================================

 Window / layout
   - Menu bar and status bar use the darkest chrome color (#161719).
   - Panels are docked in QSplitters; 3 px gaps show the window bg (#1b1c1e);
     splitter handles draw 3 small grip dots that turn blue on hover.

 Panels ("Card")
   - 1 px near-black outline (#0e0f10), radius 3, surface #222326.
   - Header strip: #2a2b2f, 1 px seam below, top corners rounded 3,
     title 13 px semibold, small ghost icon buttons on the right.
   - Inset sub-cards (inspector groups): surface bg + seam outline, radius 3.

 Buttons
   - Default: flat #303135 with #3c3e43 outline; hover #393a3f; pressed #2a2b2f.
   - Primary: solid accent, white semibold text, darker blue outline.
   - Ghost: transparent until hover.
   - Success (PLAY): solid green; switches to danger (STOP) while running.
   - Toggle buttons (3D / code): checked = 35% accent fill + accent outline.

 Text fields, spin boxes, combo boxes  ("property field" look)
   - Dark filled (#17181a), subtle 1 px outline, 1 px lighter underline (#55575d).
   - Hover: slightly lighter fill + lighter underline.
   - Focus: underline becomes 2 px accent (padding-bottom trick keeps height fixed).
   - Error: 2 px red underline + reddish outline.
   - Combo boxes use #2a2b2f fill (they look like buttons you can open).

 Tabs  (editor style, like VS Code / Omniverse)
   - Tab bar sits in a #1e1f22 strip spanning the full panel width (tabs_flush).
   - Tabs are separated by 1 px seams; inactive text is faint, hover lightens.
   - Active tab takes the content color (#222326), overlaps the pane seam by
     1 px (margin-bottom:-1px) so it merges with the content, and shows a 2 px
     accent line on TOP. No bottom underline.
   - Each tab has a 15 px icon.

 Vertical side tabs (Graph panel, West position)
   - Rotated labels, faint when inactive; active = #2a2b2f fill + 2 px accent
     line on the right edge.

 Tree view  (stage / outliner style)
   - Vertical indent guide lines (1 px, border_strong) under every expanded
     parent, no horizontal connectors (QSS border-image on !adjoins-item branches).
   - Muted chevrons for expand/collapse.
   - Full-row hover (#26282c) and selection (#283445), including the indent area
     (show-decoration-selected: 1).
   - Optional toolbar above: filter field, expand-all / collapse-all, counts.

 Tables
   - Header #2a2b2f, 11 px semibold uppercase muted labels, seam underneath.
   - Rows separated by 1 px #2a2b2f lines, no grid; selection #283445.
   - Status column drawn as small tags: radius 2, soft colored bg, dot + text.

 Lists / navigation
   - Selected item: #26282b background + 3 px accent bar on the left, radius 3.

 Check boxes / radios / switches
   - 14 px, dark fill, #5a5c62 outline; checked = accent fill with white check/dot.
   - Switch: square-ish (radius 2), accent track when on, white knob.

 Slider / progress
   - Slider: thin 3 px groove, accent fill, light 6 x 18 bar thumb (blue on hover).
   - Progress: 4 px bar, accent chunk.

 Menus / popups / dialogs / toasts
   - Elevated #2c2d31, #45474c outline, radius 3 (dialogs 4); items radius 2.
   - Menus/combo popups are frameless + translucent so the radius is real.
   - Modal dialogs are in-window overlays: window dims, card slides in, Esc closes.

 Charts (custom painted)
   - Straight lines (no smoothing), 1.8 px, light gradient area fill under the
     primary series, solid horizontal grid lines in border color,
     square hover markers, bars radius 2.

 Chrome (quiet_chrome=True)
   - Logo tile is neutral graphite with a light glyph (not accent colored).
   - Avatars are neutral slate shades (not rainbow).
   - No notification dot. Sidebar call-to-action is a normal button.
   - Status/delta badges sit on a neutral #2b2d31 background; only text is colored.


===============================================================================
 5. HOW THE STYLE IS BUILT (3 LAYERS)
===============================================================================

 The widgets are shared by all 9 styles. Style 9 is ONE data object
 (qtui/builds/workbench.py) consumed by three mechanisms:

 Layer 1 — Tokens -> base stylesheet + QPalette   (qtui/theme.py, qtui/qss.py)
   * Theme(...) holds colors, radii, control height, fonts, spacing.
   * Theme.tokens() derives the rest (hover, pressed, selection, soft alphas,
     sizes like control_inner = control_h - 2, font sizes ...).
   * qss.build() substitutes $tokens into a shared BASE stylesheet and generates
     recolored SVG icons for QSS (check marks, chevrons, calendar, indent line).
   * apply() sets: Fusion style, app font, QPalette (so non-QSS parts and
     disabled text match), then app.setStyleSheet(...).

 Layer 2 — Style-specific QSS overrides  (Theme.extra_qss)
   * Appended after the base sheet (same $tokens available). This is where
     Workbench gets: header strips, flat tool buttons, underline fields,
     editor tabs, tree guides, bar slider, dense tables, small radii.

 Layer 3 — Settings read by custom-painted widgets  (Theme fields)
   card_split_header=True   panel header becomes a separate strip
   toggle="square"          switch shape
   avatar_round=0.18        rounded-square avatars
   curve="linear"           straight chart lines
   line_width=1.8, grid="solid", bar_radius=2
   pill_radius=2, status_dot=True    table status tags
   quiet_chrome=True        neutral logo/avatars, no badge dot, plain CTA
   tabs_flush=True          tab bar spans the panel edge to edge
   panel_gap=3              splitter handle width / gap between panels
   topbar_height=52         (only used by layouts that have a top bar)


===============================================================================
 6. CHANGES NEEDED TO REPRODUCE IT IN ANOTHER QT APP
===============================================================================

 Step 1 — Application setup (before creating any window)
   app.setStyle("Fusion")                       # QSS behaves consistently on Fusion
   font = QFont("Inter"); font.setPixelSize(13)
   font.setHintingPreference(QFont.HintingPreference.PreferNoHinting)
   app.setFont(font)
   app.setPalette(<palette from section 2>)     # Window=#1b1c1e, Base=#17181a,
                                                # Text=#e6e7e9, Highlight=#4a8fe7,
                                                # PlaceholderText=#73757b,
                                                # Disabled Text=#73757b ...
   app.setStyleSheet(<Appendix A>)

 Step 2 — Icons used by QSS
   The stylesheet references small SVGs via url(...):  check (white, stroke 3.2),
   minus, dot, chevron up/down/left/right (#a6a8ae), calendar, sort arrows and a
   vertical line "vline" (#3e4045, stroke 1.3) for tree guides.
   In this repo they are generated at runtime (qtui/icons.py -> temp dir).
   In your app: ship them as resources (:/icons/...) and replace the url()s.

 Step 3 — Give widgets the object names / properties the QSS expects
   (see section 8). Without them, the generic rules still apply but you lose
   header strips, nav bar, button variants, etc.

 Step 4 — Panels
   Build each docked panel as:
     QFrame#Card
       QFrame#CardHeader  (property panel=true, min-height 34, title + actions)
       QWidget            (content, almost no margins)
   Put panels in QSplitters with handleWidth = 3 and a custom QSplitterHandle
   that paints 3 grip dots (see qtui/panels.py: _GripHandle, DockSplitter).

 Step 5 — Editor-style tabs
     QFrame#TabHost (zero margins)  ->  QTabWidget(documentMode=True)
     tabBar().setExpanding(False); give tabs icons (15 px).
   The QSS in Appendix A does the rest (strip, seams, active-tab merge).

 Step 6 — Trees
     tree.setIndentation(16..18); tree.setUniformRowHeights(True)
   QSS provides guides, chevrons and full-row selection. For the outliner feel
   add a toolbar (QFrame#PanelToolbar) with a filter field and expand/collapse.

 Step 7 — Combo boxes and menus (real rounded corners)
     combo.setItemDelegate(QStyledItemDelegate(combo))   # lets ::item QSS apply
     popup = combo.view().window()
     popup.setWindowFlags(Qt.Popup | Qt.FramelessWindowHint | Qt.NoDropShadowWindowHint)
     popup.setAttribute(Qt.WA_TranslucentBackground)
     # same flags + attribute on every QMenu you create (before it is shown)

 Step 8 — Spin boxes / time edits
     spin.lineEdit().setTextMargins(8, 0, 0, 0)   # QSS padding-left is ignored here

 Step 9 — Line edits with icons
   Do NOT use QLineEdit.addAction() for icons — with QSS min-height the icon is
   placed off-center. Use a subclass that paints the leading icon and positions a
   trailing QToolButton itself (qtui/widgets.py: IconLineEdit).

 Step 10 — Custom-painted widgets
   Anything you paint yourself must take colors/shapes from the same values
   (section 7), otherwise it will look like a different app.

 Step 11 — Overlays (dialogs, command palette)
   Prefer in-window overlays (child widget that dims the window and hosts a
   QFrame#DialogCard with a drop shadow) over top-level frameless dialogs:
   positioning and translucency are reliable on Wayland this way
   (qtui/widgets.py: Overlay; qtui/dialogs.py).


===============================================================================
 7. CUSTOM-PAINTED WIDGETS: WHAT THEY MUST READ FROM THE STYLE
===============================================================================

 These are drawn with QPainter, so QSS cannot reach them. For Workbench:

 Toggle switch (widgets.Toggle)
   40x20, radius 2 (square style), track = #3b3c3f off -> accent on (animated
   170 ms OutCubic), knob white, inset 3 px.

 Avatars (widgets.Avatar)
   Rounded square, radius = 18% of size; neutral slate fill
   (mix(surface_alt, text_muted, 0.30..0.48)); white initials (dark if fill light).

 Status tags in tables (widgets.StatusDelegate)
   Height 22, radius 2, soft semantic bg, 3 px dot + 11 px semibold text.

 Navigation indicator (widgets.NavDelegate)
   Workbench uses nav_indicator="none" — the left bar comes from QSS
   (border-left: 3px solid accent) instead.

 Charts (widgets.AreaChart / BarChart / Sparkline / DonutChart / Ring)
   Straight polyline, 1.8 px (secondary series dashed, 1.2 px), gradient fill
   26% -> 0% under the primary series, solid 1 px grid in border color, y-labels
   faint 11 px, hover crosshair + elevated tooltip box (radius 3), square hover
   markers, bar radius 2, ring caps round.

 Splitter grip (panels._GripHandle)
   Fills with bg, draws three 2 px dots in text_faint; dots turn accent on hover.

 Code editor (editor.CodeEditor)
   Background = surface, gutter = surface with a 1 px border line, line numbers
   faint (current line muted), current-line band = surface + 4.5% text,
   syntax colors as in section 2.

 3D viewport (viewport.Viewport3D)
   Vertical gradient (surface + 5% text -> bg), grid lines in border /
   border_strong, axis gizmo muted (35% toward text_faint), boxes in
   surface_alt + 12% text with accent outline when selected.

 Console (panels.Console)
   Monospace; timestamp faint, [DEBUG] faint, [INFO] muted, [WARNING] warning,
   [ERROR]/[CRITICAL] danger (critical bold).

 Note: switch size, panel insets, splitter width and baked icon colors are read
 when widgets are CREATED -> apply the style before building the window.

   QPlainTextEdit#CodeEditor, #Console   borderless editors
   QFrame#DialogCard, #Toast, QLineEdit#PaletteInput   overlays
   QFrame#Segmented         segmented control container

   QPushButton[variant="primary" | "ghost" | "danger" | "danger-soft" |
               "success" | "toggle" | "link"]
   QPushButton[size="sm"], [iconOnly="true"], [hasMenu="true"]
   QLabel[role="h1" | "h2" | "h3" | "paneltitle" | "filetitle" | "section" |
          "muted" | "faint" | "caption" | "field" | "help" | "error" | "kbd"]
   QLabel[badge="success" | "warning" | "danger" | "info" | "accent" | "neutral"]
   QLineEdit[state="error"]
   QProgressBar[kind="success" | "warning" | "danger"]

   After changing a dynamic property at runtime, re-polish:
       w.style().unpolish(w); w.style().polish(w)


===============================================================================
 9. QT PITFALLS SOLVED ALONG THE WAY (IMPORTANT WHEN PORTING)
===============================================================================

 * Semi-transparent selection colors get painted twice in item views
   (selection-background-color + ::item:selected) and look too strong.
   -> Use a SOLID mixed color for selection (#283445).
 * Colors with alpha in QSS: use #AARRGGBB (Qt order), not #RRGGBBAA.
 * QListWidget ignores ::item min-height -> set item.setSizeHint(QSize(0, 32)).
 * A border-radius larger than half the item height is silently dropped.
 * Focus underline 1 px -> 2 px would change the height; compensate with
   padding-bottom: 1px (normal) / 0px (focus).
 * Tab rules from a style must not leak into vertical tabs: scope vertical
   tab rules with an ID selector (QTabWidget#SideTabs QTabBar::tab ...).
 * Active tab merging into the pane: pane `top: -1px` + tab `margin-bottom: -1px`
   + same background as the pane, and `border-bottom: none` on the active tab
   (the base sheet otherwise adds an underline).
 * Tree indent guides: border-image on `::branch:!adjoins-item` (both has-siblings
   and !has-siblings), then `border-image: none` + chevron image on branches with
   children, otherwise the line image covers the arrows.
 * QSS `padding` does not move the text of QSpinBox/QTimeEdit -> textMargins.
 * Drop-shadow and opacity effects can't be combined on one widget
   (one QGraphicsEffect per widget) — toasts fade, dialogs get the shadow.
 * Menus/popups need FramelessWindowHint + NoDropShadowWindowHint +
   WA_TranslucentBackground BEFORE first show for rounded corners.


===============================================================================
 10. TUNING KNOBS
===============================================================================

   Denser, closer to Isaac Sim   font_px=12, control_h=28, panel_gap=2
   Softer                        radius=4, radius_lg=4
   Different accent              accent / accent_hover / accent_pressed
                                 (keep accent ~ L 55-60%, S 70-80%)
   More contrast                 text_muted -> #b4b6bc, text_faint -> #808288
   Show decorative color again   quiet_chrome=False
   Inset tabs instead of strip   tabs_flush=False
   Smooth charts                 curve="smooth"
